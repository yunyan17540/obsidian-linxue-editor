# AI智能陪写系统

Obsidian 第三方插件。它读取当前正在写的笔记，把内容发给你自己的文本接口，再把陪写身份的点评交给语音接口朗读。

默认身份叫林雪，是青梅竹马，也是编辑。设置里的「AI身份名称」可以改成别的名字，面板标题、状态栏、右键菜单、提示和语音都会跟着改。她会说明自己理解了什么、哪里真正成立，再指出不足和可以动手的改法。三种说话模式：

- 话痨：先闲聊，再把理解、亮点、致命问题、重要问题、细节、改法和下一步说全。
- 淑女安静：低声、短句，只点最要紧的一两处不足和一条改法。
- 中庸：按改稿节奏说完，大约一口气能听完。

插件不接入本地模型。文本和语音都走你填写的 HTTP 接口，密钥存在当前库的 `.obsidian/plugins/linxue-editor/data.json`。

## 安装

需要 Node.js。在本目录执行：

```powershell
npm install
npm test
npm run build
```

也可以从 [Releases](https://github.com/yunyan17540/obsidian-linxue-editor/releases) 下载 `linxue-editor-0.1.0.zip`，解压到库的 `.obsidian/plugins/linxue-editor/`。压缩包里只有这三个文件：

- `main.js`
- `manifest.json`
- `styles.css`

然后在 Obsidian 里关闭安全模式，启用「AI智能陪写系统」。

发布包和仓库都不含接口地址、密钥或点评历史。这些内容只存在你自己的库里，由你在设置页填写并保存。

## 设置

打开设置 → AI智能陪写系统。填完地址、密钥和模型后，点页面底部的「保存」。测试、试听和检测也会先保存当前内容。密钥存在当前库的 `.obsidian/plugins/linxue-editor/data.json`。

文本接口使用兼容 OpenAI Chat Completions 的根地址，插件会请求 `{根地址}/chat/completions`。常见写法是 `https://api.openai.com/v1`，也可以换成 DeepSeek、Moonshot、OpenRouter 或自建网关。填写模型名。需要特殊鉴权时，把额外请求头写成 JSON 对象。

语音接口有两种：

- OpenAI 兼容：请求 `{根地址}/audio/speech`，填写模型（如 `tts-1`）和音色（如 `alloy`）。
- 自定义 HTTP：填写完整 URL 和请求体。占位符会替换成 JSON 字符串，不要再加引号：

```json
{
  "model": {{model}},
  "voice": {{voice}},
  "input": {{text}}
}
```

返回值可以是音频字节，也可以是 JSON 里的 Base64。Base64 路径写成 `audio` 或 `data.audio`。

点「检测可用语音」后：

- 地址属于阿里云百炼（`maas.aliyuncs.com` 或 `dashscope.aliyuncs.com`）时，朗读改走 `POST /api/v1/services/audio/tts/SpeechSynthesizer`。百炼没有 OpenAI 的 `/audio/speech` 和 `/audio/voices`，所以这两个地址会返回 404。模型和系统音色使用百炼公开目录，检测时会用当前密钥试合成一个字，确认接口能通。可用模型是 `qwen-audio-3.1-tts-flash`、`qwen-audio-3.0-tts-plus`、`qwen-audio-3.0-tts-flash`。名称里带 `realtime` 的是实时对话模型，不能用来朗读。
- 其他 OpenAI 兼容地址会请求 `{根地址}/models`，留下名称里带 tts、speech、audio、voice 的模型，再请求 `/audio/voices` 和 `/voices`。

查到的模型和音色会出现在下拉框里；当前值不在列表中时，会自动选中第一项。接口没有音色目录时，检测说明会写明，音色仍可手填。自定义地址如果以 `/audio/speech` 结尾，根地址会从这里截出来；否则按该地址的站点加上 `/v1` 查询。

更新插件文件后，在命令面板运行「重新加载陪写插件」。Obsidian 的 `Ctrl+R` 会走编辑器快捷键，不会重新加载插件。

温度填 `0` 时按模式自动选择：话痨 0.9，中庸 0.7，淑女安静 0.45。人设提示词可以改，恢复默认会回到原稿。模式说明和当前名字由插件附加在人设后面。

## 使用

打开一篇文稿，点左侧丝带图标，或在命令面板运行「点评当前文稿并朗读」。选中一段后，可以用「点评选中文字并朗读」，或在编辑器右键菜单里让当前身份听听这段。

右键菜单里的「让{AI名称}替我续写」会顺着选区或光标往下写一段，插在光标后面，不覆盖已有文字。没有选区时，它使用光标前大约二百四十字作为衔接。面板里的「替我续写」和命令「请求替我续写」做同一件事，`Ctrl+Z` 可以撤回。

设置里的「自动点评」默认关闭。打开后按填写的分钟数查看当前文稿新写的内容，默认 15 分钟，最少 1 分钟。新内容不足 1 个字或符号就跳过。新内容不足 15 个字时，不点评情节，只朗读一句关心，问你是不是卡文了。达到 15 个字才按普通点评处理，并且只看这一阵新写的部分。

同一处右键菜单还有「向{AI名称}请求帮忙润色」。它只把选中的文字交给文本接口，并带上很短的前后文帮助衔接。返回的正文会替换选区，可用 Ctrl+Z 撤回。润色期间如果原文变了，插件不会写入，结果留在面板里。面板工具栏的「润色选区」和命令「请求润色选中文字」做同一件事。润色结果也会进入点评历史，原文和润色稿都留着。

右侧面板会留下文字稿，方便对照。每次点评成功后，文字稿会记入面板下方的「点评历史」，最多保留 40 条。点一条可以重新打开，单条可以删除，也可以清空。历史存在插件目录的 `history.json`，不含密钥。朗读是分段合成的，点「停止」或运行「停止朗读」会打断。状态栏显示「名字 · 模式」，点它可以打开面板。命令「切换说话模式」在话痨、淑女安静、中庸之间轮换。

文稿超过「送审字数上限」时，只发送光标附近的一段，并告诉陪写身份前面被截掉了。空笔记不会发请求。

文本接口失败时不会朗读。语音接口失败时，文字稿仍留在面板里。
